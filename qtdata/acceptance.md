# 如何验收

## 两道验收各自回答一个问题

**第一次：商务验收。**商务经理回答：「这是不是我们当初答应客户交付的东西？」——检查有没有按照约定完成。约定写在需求确认单里，所以验收是对单，不是凭印象。

**第二次：客户验收。**客户回答：「这是不是我需要的东西？」——检查结果有没有解决实际问题。

两道验收不是重复：**内部验收检查「有没有按照约定完成」，客户验收检查「结果有没有解决实际问题」。**公司对客户的承诺由第一道守，客户真正的目的由第二道验——谁也替代不了谁。

## 没有验收标准，就没有真正意义上的交付

验收标准必须在开工前定义，不是交付后补写。案例订单的验收表：

| 验收项目 | 标准 |
|:---------|:-----|
| 网站覆盖 | 300/300 |
| 数据抓取 | 成功率 ≥ 95% |
| 字段完整性 | 必填字段完整 |
| 重复数据 | 无明显重复 |
| 更新时间 | 每天 08:00 前，符合约定频率 |
| 输出格式 | CSV + 数据库 |
| 数据量 | ≥ 约定条数 |
| 异常记录 | 有抓取日志，失败站点可追溯 |
| 示例结果 | 抽查 10 条通过 |

表里没有的项目，验收时提不出来；开工前没定义的指标，交付时算不出对错。**验收表和需求确认单是同一件事的两面：一个在开工前定义「要什么」，一个在交付时核对「给了什么」。**

## 商务验收的动作

1. 逐项对照需求确认单与验收表，写出结论：通过，或不通过加不通过项清单
2. 不通过项退回对应任务单，注明差距（哪项、差多少）
3. 全部通过后，才向客户提交交付

## 客户验收的动作

1. 按约定方式交付：格式、位置、时间与需求确认单一致
2. 请客户按验收表核对，并明确回复确认——口头「收到」不算验收通过
3. 客户提出的新要求，与验收表比对：表内未覆盖的，按范围变化处理（见「出问题怎么办」），当场不做任何口头承诺
