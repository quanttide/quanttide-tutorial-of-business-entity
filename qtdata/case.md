# 一个完整订单：从客户一句话到最终交付

本章把前面各章的动作连起来走一遍。案例（虚构，综合真实订单构造）：一家科技公司希望长期跟踪 300 个海外科技网站，每天获取最新文章，并整理成结构化数据。

## 1. 客户第一句话

> 「我们希望长期跟踪一些科技网站，有新文章就帮我们整理出来。」

陌生客户、需求模糊——不报价，先开需求评审会：商务与技术凑在一起看三件事——客户的业务意图是什么（每天要什么、给谁用）、初步拆解方向（抓取类现成单元为主，转载去重可能要新增）、由谁去追问客户。

对接人随后走需求八问，产出需求确认单：300 个站点（客户提供清单）、每天一次、字段清单、过去一年历史数据、CSV + 数据库、验收定义与预算区间全部写入，不做清单记录本期不含的热点汇总——**范围确认完成**。

## 2. 拆解

按标准单元链条拆：数据源清单 → 采集 → 解析 → 清洗 → 去重 → 结构化 → 存储 → 更新。绝大多数单元是现成的；「转载去重规则」客户有特殊口径，标为本单新增项，单独评估并计入工作量。

## 3. 报价与签单

按单元出任务单（输入、输出、参数、验收标准、负责人五项齐全），套报价公式估算，报价落在客户接受区间内，双方确认需求确认单后签单。

## 4. 执行

建立订单档案，按任务单执行并记录。第 12 天某站点改版导致解析失败：记录改版点 → 对照范围（站点维护属原范围）→ 按现有单元调整解析规则 → 按原验收标准复验通过 → 过程写入异常记录。全程没有临时开发，没有口头改约。

## 5. 内部验收（商务验收）

商务按验收表逐项核对：覆盖率 300/300、成功率 97%、必填字段完整、每日 08:00 前更新、抓取日志可追溯、抽查 10 条通过——**通过**，向客户提交交付。

## 6. 客户验收

客户核对后回复确认。随后提出希望每周汇总 Top 20 热点——对照需求确认单：此项在不做清单里，不在原范围 → 记录 → 交商务 → 与客户确认为追加需求，走下一个订单流程。**当场没有口头承诺。**

## 7. 沉淀

本单留下三样可复用成果：改版解析的处理方法（进单元卡片的常见问题）、转载去重规则模板（新单元卡片）、更新后的爬虫单元卡片。下一单同类需求，从这些成果起步，不再从零开始——这就是下一章要讲的机制。
