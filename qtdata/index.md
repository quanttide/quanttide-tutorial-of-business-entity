# 量潮数据工作模式

量潮数据面向国内外高校科研团队与高新科技企业提供数据处理服务。本篇总结这项业务的工作模式：一个订单如何进来、如何被交付、以及为什么这样设计。

## 业务性质：标准化的定制业务

「定制」指根据企业自己的需求来调整；「标准化」指内部有一套现成的、可复现的单元。合在一起：模糊的业务诉求进来，标准的程序单元出去。

## 工作流程：五步双重验收

1. 商务经理跟客户确认
2. 签单完成后执行
3. 执行完成后，商务经理根据跟客户的交付进行验收
4. 验收完成后交给客户
5. 客户再进行二次验收

接单的第一步是范围确认。客户需求五花八门，一般只有一个模糊的方向和一个模糊的价格范围——先确认这个范围在不在客户的接受范围之内。范围确定之后，在预算之内最大限度地满足客户的需求，让客户看得到比较明显的结果。

需求拆解成标准单元的例子：客户想要长期跟踪一批网站的最新信息，对应的是「爬虫 + 清洗 + 精炼」一条龙的程序，重心在爬虫——获取数据是关键。需求越能拆成现成单元，交付越可控。

## 配置与收益结构

- **最低配置**：一位商务经理加一位数据工程师
- **工作量的大头在商务**：跟客户的沟通主要都由商务负责
- **收益取决于谈单**：「这个业务能挣多少钱，主要取决于商务经理的单谈的怎么样」；技术方面在标准化之后，大部分人只要上手都能干

## 为什么这样设计

**本质是技术管理，不是个人能力。** 需求拆解——把模糊的业务诉求变成可执行的工程任务；过程管控——每一步都有标准，每一个交付物都有验收准则；质量兜底——出了问题能回溯、能归因、能改进。这套体系不靠牛人运转，靠制度和工具。

**技术可复现，因而可替代。** 标准化单元让初级人力可以上手，技术执行不是稀缺环节。

**商务不可标准化，因而是稀缺环节。** 判断与谈判发生在技术介入之前，议价权与瓶颈都在商务侧——这是资源投向商务经理培养的结构性理由。

**双重验收兜底。** 交付先过内部商务验收再出公司，客户再验一次——质量责任在两道闸之间不悬空。

## 拆解一个订单

分析商务案例时，抓住三个节点就是抓住了一个订单的完整生命周期：

1. **范围怎么谈下来的**：模糊报价到确认接受区间
2. **需求怎么变成标准单元的**：业务诉求到程序模块
3. **价值怎么被验收的**：双重验收让「明显的结果」成为可交付之物
