# 为什么我们这样工作

前面七章是「怎么做」，这一章是「为什么」。先学会做，再理解理由——顺序不能反。

## 五个词

- **标准化**：面对客户时做定制，面对组织内部时做标准化。客户需求各不相同，执行动作可以相同
- **可复现**：同一类需求第二次出现时，不需要重新研究怎么做
- **可交接**：订单档案与任务单是为「没参与过的人」而写的——人可以换，订单不断
- **可验收**：标准在开工前定义，交付时才算得出对错
- **持续沉淀**：每个订单产出方法、模板、卡片，成为下一个订单的起点

## 每做一个订单，都应该让下一次更容易

这是整套体系真正的核心机制。一个能力的养成路径是这样的：

```text
第一次遇到一个网站：人工研究怎么抓
第二次：            把方法记录下来
第三次：            形成一个爬虫模板
第四次：            形成一个标准单元
第五次：            新人按照 SOP 就可以完成
```

**个人经验 → 方法 → SOP → 标准单元 → 组织能力。**

公司和客户的每一单都在走这条路。它解释了为什么执行章要求过程记录、为什么没有卡片的单元要补建卡片、为什么验收不通过要退回而不是将就——三个看似繁琐的规定，都是同一条流水线上的闸门。

## 技术的价值在于被标准化

技术工作的意义不只是把这一单做出来，而是把做法变成后面的人都能执行的东西。**标准化以后，个人经验才变成组织能力，新人也才有机会从第一天就做出合格交付。**

对在校生来说，这是进入这个行业最实的路径：你积累的不是「干过几个项目」，而是「沉淀下几个别人也在用的标准单元」。前者跟着简历走，后者跟着组织走。

## 为什么分两道验收

内部验收保证「按约定完成」，客户验收保证「解决了问题」。约定是公司对客户的承诺，问题的解决是客户真正的目的——两道各管一半。少了第一道，承诺会漂移；少了第二道，交付会变成自说自话。

## 闭环

```text
客户需求 → 范围确认 → 标准化拆解 → 标准化执行 → 内部验收 → 客户验收 → 反馈 → 沉淀为新的标准单元
```

最后一环接回第一环：沉淀下来的单元，让下一次的范围确认更快、拆解更准、报价更实。这就是「把一次性的客户需求，转化成可以重复执行的组织能力」——本教程第一章的第三条原则，到这里你应该能亲手验证它了。
